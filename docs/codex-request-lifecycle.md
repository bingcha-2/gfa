# Codex 请求生命周期与恢复边界

## 行为

- HTTP 生成及 relay 请求绑定客户端取消信号。等待上游或退避期间取消后立即退出；流中取消保留已解析用量，标记为客户端取消。
- WebSocket 任一方向结束后关闭两端连接，并等待两个转发协程退出后再汇总。仅上游帧可以提供计量数据。
- HTTP JSON、SSE、WebSocket 共用错误分类，保留上游错误码。SSE/WS 的明确失败按失败上报，同时保留已解析用量。
- 只有完整、最大 64 KiB、具有已知长度的 HTTP 503 JSON 容量拒绝（`server_is_overloaded` 或 `slow_down`）可以原账号、原地址重试一次。含 output、usage 或 response 字段的响应不重放。
- 默认退避一秒；尊重 `Retry-After` 秒数或 HTTP 日期。需要等待超过五秒时原样返回，不提前重试。
- 流式 SSE/WS 不自动重放、不改写上游错误码。认证、权限、额度错误及结果不明的传输错误不重放。生成请求的绑定代理失败也不再切换网络出口重放；只读额度查询的原行为不变。

## 自测

新增测试使用本地 HTTP/WebSocket 假上游，无须真实 OpenAI 账号：

- 两次请求上限，凭据、会话标识与请求体不变。
- 认证、额度、未知错误、超大响应及流式错误保持字节不变。
- 取消中断退避，HTTP 客户端取消传递至上游。
- WebSocket 客户端断开后关闭上游，客户端上传的伪 usage 不计量。
- SSE 失败保留用量、只上报一次、不按 HTTP 200 误记成功。
- HTTP JSON、SSE、WebSocket 错误分类一致。

运行 `go test ./... -count=1 -timeout 180s`。Windows 下将 `APPDATA` 指向专用测试目录，避免已有配置相关测试使用真实用户配置。Wails 编译需要 `frontend/dist`；Go 后端测试可提供非发布用途的占位嵌入文件，正式客户端构建必须使用真实前端产物。

本次没有新增中央并发队列，也没有更改账号授权、凭据分发或设备证明机制。请求恢复不能保证账号访问权限恢复。

## 2026-09-15 全量失败修复

此前的 74 个顶层失败主要由重复的共因触发：

- SQLite 测试连接未关闭；Hub 缺少关闭入口，后台任务和账号库一直存活。新增幂等 `Close`，取消并等待后台循环、停止网关、关闭数据库，测试清理时调用。
- Windows 路径分隔符导致配置测试回读错误、危险挂载路径漏判；备份路径中的盘符冒号导致写入失败。改用标准路径处理，备份文件名使用完整路径的 SHA-256，另测路径扁平化碰撞。
- 测试仅设置 `HOME`，未隔离 Windows 的 `USERPROFILE` / `APPDATA`，造成配置与账号数据跨测试累积。补齐隔离，并按文件实际初始权限验证清理前后权限保持。
- Codex 停止与 Antigravity 启动的测试保护不完整；修复测试模式下的入口短路。本进程身份判断直接识别当前 PID，其余 PID 保持无法确认即拒绝的逻辑。
- 本机 `tasklist` 集成测试受执行沙箱权限影响，改为通过 `BCAI_RUN_PROCESS_INTEGRATION=1` 显式启用。默认测试继续验证中英文输出和进程记录解析。

修复后：`go test ./... -count=1 -timeout 180s` 和 `go vet ./...` 全部通过。额外在允许只读进程查询的环境中，单独启用并运行 `TestTasklistMissingImageOnWindows`，结果通过。正式安装包与生产环境尚未验证或部署。
