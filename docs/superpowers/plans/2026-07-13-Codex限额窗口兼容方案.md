# Codex 限额窗口兼容方案

## 一、问题结论

GFA 当前把 Codex 上游接口的两个字段位置写死为：

```text
primary_window   = 5 小时额度
secondary_window = 每周额度
```

现在已经观察到新的返回形状：

```text
primary_window.limit_window_seconds = 604800
secondary_window = null
```

`604800` 秒等于 7 天，所以这个 `primary_window` 实际上是每周额度。GFA 如果继续按位置读取，就会把每周额度显示成 5 小时额度。

根因不是“第二格被取消”，而是：**字段位置不再代表固定的窗口类型。**

## 二、总方案

只改 Codex，不改 Claude。

Codex 收到上游额度后，不再根据 `primary_window`、`secondary_window` 的位置判断，而是读取每个窗口自带的 `limit_window_seconds`：

```text
18000 秒  → 5 小时窗口
604800 秒 → 每周窗口
其他时长 → 暂时无法识别，不猜
```

归类完成后，仍然转换成 GFA 现有的“5 小时 + 每周”内部结构，因此后面的选号、额度展示和公平分配不需要整体推倒重写。

## 三、怎么判断窗口状态

每个标准窗口需要表达三种状态：

### 1. 存在

成功返回，并识别到对应时长。

例如：

```text
limit_window_seconds = 604800
```

表示本次明确返回了每周窗口。

### 2. 本次明确未返回

接口请求成功，所有返回的窗口都可以识别，但其中没有 5 小时窗口。

例如：

```text
primary = 每周窗口
secondary = null
```

这时只能得出“本次没有报告 5 小时窗口”，不能宣称 OpenAI 永久取消了它。但对 GFA 来说，应该清掉以前保存的旧 5 小时额度，避免旧数据继续参与选号。

### 3. 无法判断

以下情况都算无法判断：

- 请求失败；
- 返回内容不是合法 JSON；
- `rate_limit` 整段缺失；
- 窗口没有时长，而且无法使用兼容规则判断；
- 出现 1 天、30 天等 GFA 尚未认识的新窗口。

无法判断时保留上一次有效数据，不清空、不伪造 100%。

## 四、兼容旧返回

正常情况下按时长识别。

只有一种情况允许使用旧的位置规则：

```text
primary 和 secondary 同时存在
并且两个窗口都没有 limit_window_seconds
```

此时暂时兼容为：

```text
primary   → 5 小时
secondary → 每周
```

如果只有一个没有时长的窗口，则无法知道它是 5 小时还是每周，不能猜，应保留旧数据并记录安全日志。

## 五、数据结构怎么改

在现有百分比字段之外，给 Codex 增加两个可选状态字段：

```text
hourlyPresent
weeklyPresent
```

含义：

```text
true  = 本次明确看到了这个窗口
false = 本次成功响应明确没有这个窗口
不传  = 无法判断，保持旧行为
```

这两个字段必须是可选的，以兼容新旧客户端和服务端：

- 老客户端不会发送它们，新服务端继续按旧逻辑处理；
- 新客户端发送它们，老服务端会忽略多余字段；
- 新客户端和新服务端同时使用时，才能准确清除已经消失的旧窗口。

服务端必须把这两个字段按三态单独持久化，不能再根据“百分比字段是否存在”反推。否则旧格式响应中的“无法判断”会在重新读取账号后被错误升级成“明确不存在”。同时保存本次快照的观测时间，较旧的重试不得覆盖较新的窗口状态。

## 六、需要修改的三条 Codex 解析路径

仓库里有三处独立的 Codex 上游额度解析，必须一起改：

1. Wails 租号客户端额度同步：`apps/app/codex_quota_sync.go`
2. 本地自有 Codex 账号额度刷新：`apps/app/internal/local/quota/quota.go`
3. 服务端手动获取额度：`apps/server/src/leasing/remote-codex/auth/codex-usage.ts`

两处 Go 解析器保留各自的百分比、reset 和输出结构，但共用 `internal/codexquota` 中的纯窗口分类器，统一维护时长常量、旧位置兜底以及 present/absent/unknown 判定。服务端 TypeScript 使用相同规则和测试样例；不把三条业务解析路径合并成通用额度框架。

## 七、旧 5 小时数据怎么处理

当前代码把 `-1` 当成“本次不知道”，因此会保留旧值。这个规则对接口失败是正确的，但无法处理“窗口确实不再返回”。

新规则：

```text
无法判断
→ 保留旧值

hourlyPresent = false
→ 清除旧 5 小时百分比
→ 清除旧 5 小时重置时间
→ 5 小时窗口不再参与选号和公平分配

weeklyPresent = true
→ 更新每周额度
→ 只用每周额度作为当前限制
```

如果以后 5 小时窗口重新出现，解析器识别到 `18000` 秒后，会自动恢复 5 小时额度，不需要再次改代码。

## 八、服务端选号和公平分配

服务端保存窗口状态后，需要重新计算当前真正限制账号的窗口：

- 5 小时和每周都存在：取剩余额度更低的一个；
- 只有每周：每周直接作为限制窗口；
- 只有 5 小时：5 小时直接作为限制窗口；
- 两个都无法判断：保持旧状态，不制造满额数据。

清除 5 小时窗口时，必须同时清除旧的 5 小时公平分配输入，不能让已经过期的 5 小时百分比继续压低账号权重。

窗口存在状态和百分比快照使用同一套因果顺序：按 `observedAt/fetchedAt` 接受新状态，乱序到达的旧快照不能重新激活已经消失的窗口。

## 九、界面怎么显示

### Codex 当前只有每周窗口

显示：

```text
本周  72%
```

不显示 5 小时这一行。

### 无法判断额度

显示：

```text
额度未知
```

### 同时存在两个窗口

继续显示：

```text
5 小时  80%
本周     72%
```

不能再把 `-1` 压成红色 `0%`，因为未知和用尽不是一回事。

## 十、Claude 明确不改

本次不修改：

- Claude 上游额度解析；
- Claude 的 5 小时和每周字段；
- Claude 的持久化逻辑；
- Claude 的公平分配规则；
- Claude 的界面显示规则。

Codex 和 Claude 当前共用部分血条转换代码。实现时不能通过修改共享默认行为来完成，而应只给 Codex 增加窗口存在状态，并在 Codex 展示分支里隐藏明确不存在的窗口。

最后必须增加 Claude 回归测试，确认 Claude 仍然显示原来的两条额度。

## 十一、日志要求

只记录窗口结构，不记录敏感数据。

允许记录：

```text
primary_present=true
primary_seconds=604800
secondary_present=false
secondary_seconds=null
```

禁止记录：

- access token；
- refresh token；
- Authorization 请求头；
- 邮箱和账号编号；
- 原始接口返回全文。

## 十二、测试清单

必须覆盖：

1. 老格式：primary 是 5 小时，secondary 是每周；
2. 新格式：primary 是每周，secondary 是 null；
3. 两个窗口位置交换；
4. 只有 5 小时窗口；
5. 只有每周窗口；
6. 两个窗口都没有时长的旧格式；
7. 只有一个窗口且没有时长；
8. 出现未知窗口时长；
9. 窗口存在但 `used_percent` 缺失；
10. 请求失败时保留旧值；
11. 成功确认 5 小时未返回时清除旧值；
12. 只有每周窗口时，选号只使用每周额度；
13. Codex 界面只显示每周；
14. Claude 仍然显示 5 小时和每周；
15. 新旧客户端与新旧服务端交叉兼容。
16. 窗口存在但 `used_percent` 为 null 时保持 unknown，不写 100%；
17. `used_percent` 为小数时三条解析路径都能正常解析；
18. 一个窗口有百分比但没有 reset 时仍视为存在；
19. 换号后的 partial 响应不能继承上一账号的展示额度；
20. 较旧双窗口快照不能复活较新的 weekly-only 状态；
21. binding 窗口变化且新窗口无 reset 时清理旧 reset；
22. 导入导出保留窗口三态与观测时间。

## 十三、实施顺序

1. 先写新旧返回格式的失败测试；
2. 在两条 Go 解析路径内实现相同的时长归类规则；
3. 保留旧响应的位置兼容逻辑；
4. 实现服务端 TypeScript 归一化；
5. 增加窗口存在状态并处理旧值清除；
6. 修正服务端选号和公平分配输入；
7. 修改 Codex 界面显示；
8. 添加 Claude 不受影响的回归测试；
9. 运行全部 Go、服务端和前端测试。

## 十四、验收结果

修复完成后，新响应：

```text
primary = 604800 秒
secondary = null
```

必须得到：

```text
5 小时窗口：本次未返回，不参与计算，不显示
每周窗口：正常更新、正常显示、参与选号
Claude：完全不变
```

未知或异常响应则保持旧数据，并留下不含敏感信息的结构日志。
