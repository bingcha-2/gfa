# 独享、拼车与超卖额度展示设计

> 日期：2026-07-12
> 状态：已实现并通过全量回归
> 范围：绑定母号的 5 小时与周窗口额度展示、服务端准入和端到端回归

## 1. 业务规则

展示方式由当前订阅类型决定，不由母号中是否混有其他类型决定：

| 母号组成 | 当前订阅 | 展示 |
|---|---|---|
| 仅拼车，未超卖或超卖 | 拼车 | 双血条：我的总剩余 + 账号总剩余 |
| 单个独享 | 独享 | 单血条：只显示个人剩余 |
| 多个独享超卖 | 独享 | 每个用户只显示自己的个人剩余 |
| 独享与拼车混合 | 独享 | 单血条：只显示个人剩余 |
| 独享与拼车混合 | 拼车 | 双血条：我的总剩余 + 账号总剩余 |

超卖只改变后台为每张卡分配的实际份额，不改变展示样式。独享用户的实际份额映射为个人 `100%`，只扣归因到该用户的消耗；不得再乘母号剩余，也不得用母号剩余封顶个人血条。拼车继续使用名义席位口径隐藏超卖。

后台始终执行母号硬上限：所有卡的有效可用额度之和不得超过母号剩余。个人血条非零但母号因未归因消耗暂时不可用时，后台阻止请求并显示“上游额度恢复中”，不能把未知消耗伪造为该用户的个人消耗。

## 2. 技术方案

服务端为每张卡、每个窗口同时计算两个值：

```text
personalFraction = (share - attributedShare) / share
effectiveFraction = personalFraction × accountScale
```

- `personalFraction`：个人账面剩余，只受归因到该卡的消耗影响；供独享单血条展示。
- `effectiveFraction`：经过母号守恒缩放的有效剩余；供请求准入和拼车展示。
- `accountFraction`：母号上游真实剩余；只作为拼车第二层展示。

现有准入、权重、`D = max(N, Σw)`、模型 CU 倍率、5 小时/周窗口归因和超卖绑定规则保持不变。只拆分“个人展示值”和“后台有效值”，不新增额度池，不新增历史窗口表，不修改数据库结构。

数据契约在 `fairShareQuota` 与 `weeklyFairShareQuota` 中新增可选 `personalFraction`，并贯通 lease、report-result、heartbeat、Go 客户端状态和前端 store。新客户端规则为：

- 独享：使用 `personalFraction`，隐藏账号层；旧服务端缺字段时回退现有 `fraction`。
- 拼车：继续使用 `fraction` 和 `accountFraction` 渲染双血条。
- 请求放行：始终使用服务端内部 `effectiveFraction`，不得使用展示值。

诊断日志同时记录 `accountFraction`、`personalFraction`、`effectiveFraction`、`accountScale`、`attributedShare`、`unattributedShare`、`resetAt`、`revision` 和事件 ID，保留 3 天。

本设计覆盖并替代旧文档中“独享使用母号封顶”“独享跳过或共用拼车 scale”“无需后端契约变更”等相冲突描述。

## 3. 端到端测试

端到端测试必须由真实服务端额度引擎经过 lease/report/heartbeat/Go 状态同步到前端组件，不允许只用前端 mock 代替。至少覆盖：

1. 仅拼车：未超卖、超卖，均保持双血条且后台守恒。
2. 单个独享：只显示个人单血条，个人消耗连续扣减。
3. 多个独享超卖：各自只扣自己的消耗，任一用户耗尽后被单独限制，所有实际额度总和不超过母号。
4. 独享与拼车混合：独享显示单血条，拼车显示双血条，两者共用同一母号硬上限。
5. 5 小时和周窗口：分别消耗、分别重置、`resetAt` 变化，互不串窗。
6. 生命周期：冷启动、服务重启、客户端重启、窗口恢复后数据一致。
7. 成员变化：用户中途加入、退出、换订阅、换母号、独享与拼车互换，不继承旧卡血条。
8. 时序极限：快照先到、上报后到；上报先到、快照后到；重复、乱序、迟到上报均可重算且不突破母号。
9. 上游修正：母号下降、回升、归零、官方重置时，准入与展示按各自语义更新。
10. 模型差异：Codex 与 Claude 不同模型、缓存、输出和 Fast 倍率正确进入 CU，展示规则不因模型改变。
11. 兼容性：新客户端连接旧服务端、旧客户端连接新服务端均不崩溃；缺少新字段时安全降级。
12. 全量回归：超卖销售、独享绑定、拼车绑定、请求准入、账本恢复、金额计价和既有客户端功能不受影响。

验收必须同时证明两条不变量：独享展示只反映个人归因剩余；后台任何时刻都不会放出超过母号真实剩余的有效额度。
