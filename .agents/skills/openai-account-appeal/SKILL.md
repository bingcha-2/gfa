# OpenAI 账号复核与申诉

在用户指定的账号范围内，通过官方渠道提交真实、可核验的情况，并逐账号核对受理结果。支持复核不代表官方确认存在降权，也不保证恢复。

## 范围与账号核验

- 区分准备草稿、实际提交和查询进度。用户已经明确要求提交时，沿用该授权完成必要步骤；仅加载本 skill 不代表允许发送消息。新增账号或不同诉求不能从旧授权推定。
- 先核对已有工单/会话，已有同一问题的申请优先补充或查询，避免重复提交。批量请求逐账号处理，除非用户要求合并报告。
- 从 `apps/server/src/leasing/rosetta/codex.service.ts` 及运行配置确认实际 `ctx.dataDir`。不要假定开发目录就是生产数据目录。
- `codex-accounts.json` 的 `accounts` 按用户指定的内部 ID 筛选，只输出核对所需字段，例如 `id`、脱敏邮箱、`planType`。不要输出整个账号对象、accessToken、refreshToken、代理凭据或 session。
- 如用户授权登录邮箱，主账号池与 `codex-precharge-accounts.json` 应按规范化邮箱关联，两个文件的 ID 不应直接关联。只取目标账号所需凭据，通过当前工具支持的安全方式使用，不回显、不存入临时报告或仓库；工具无法安全提供凭据时交由用户登录。
- 内部母号 ID 不是 OpenAI 组织 ID、API 密钥 ID 或官方工单号。

## 选择渠道和事实

1. 生成失败、响应质量或服务异常：使用 [OpenAI 帮助中心](https://help.openai.com/) 提交技术支持/复核请求。
2. 实际收到警告、停用或封禁通知：核对目标账号的通知，按通知提供的官方申诉入口处理。验证实际域名；带令牌的申诉链接不得写入 skill、仓库或最终回复。
3. 只描述当前账号的证据：模型、客户端版本、时间和时区、错误内容、对应 request ID、是否通过第三方集成、已验证的复现方式。没有的信息直接说明未知，不能借用其他账号的数据。
4. HTTP 200 内的流式失败不算生成成功；配额上报成功不说明生成可用；本地 502/EOF 不足以证明账号降权或封禁。将用户报告和实际验证明确区分。

撰写内容时按需读取 [references/messages.md](references/messages.md)。模板不是可以无条件照搬的事实声明。

## 登录与邮箱验证

使用当前环境提供的浏览器工具，先读取工具文档和页面状态，再按实际元素操作。不能从本 skill 猜测 API、动态 URL、选择器或隐藏接口。

- 逐账号核对当前登录身份，切换账号时使用正常退出/其他账号登录流程。只有“Log out”按钮不能证明登录的是目标邮箱；不确定时先核验身份再发送。
- 只读取授权账号的相关登录验证码、官方通知和支持回复。验证码必须匹配收件人及本次登录时间；过期后重新申请一次，反复失败则报告阻塞，不循环发送。
- 不导入 OAuth cookie、不绕过验证、不为提交申诉修改密码或 MFA。遇到需要用户操作的验证时，保留进度并明确所需操作。
- 邮箱和帮助中心的具体页面处理经验见 [references/browser-notes.md](references/browser-notes.md)，仅在相关页面出现时读取；以当前页面为准。

## 帮助中心提交与人工转接

1. 打开官方帮助中心，在已核实的目标账号下进入支持聊天，检查是否已有对应会话。
2. 提交简洁的真实问题描述。必要时回答支持机器人追问；缺少证据时如实说明，不编造时间、请求 ID 或排障结果。
3. 用户要求申诉/人工复核时，明确请求转交人工。若页面出现确认转接步骤，完成确认并等待实际受理提示。
4. “发送成功”“按钮变灰”“加载中”不等于人工受理。以页面明确的转交支持专员或表单成功确认作为结果；例如出现 “Escalated to a support specialist” 才可报告已转人工。
5. 超时或状态不明时，先检查同一会话是否已有回复；不要再次发送同一申请。记录待核实状态后继续其他独立账号。

## 正式申诉表单

- 根据通知和用户提供的真实原因填写，不为了绕过必填字段而改选原因。
- 组织 ID 或 API 密钥 ID 缺失时不能随机填写、使用内部账号 ID 或截取 OAuth token 代替。表单允许“不适用”时如实填；必填且不接受时，通过帮助中心说明字段不适用于 Codex OAuth，请人工提供正确流程。
- 事件起止时间、密钥是否撤销等按当前账号核实，不能继承另一账号的事件。尚未验证的用户陈述明确归因于用户。
- 不因登录错误推定账号遭盗；不声称没有违规、仅个人使用或已完成排障，除非有事实依据。

## 结果核对

逐账号报告以下实际状态之一：草稿就绪、等待登录/验证、已发送给支持机器人、已确认转人工、表单已确认提交、提交状态待核实或被具体字段阻塞。

只记录必要的账号内部 ID、提交时间、渠道、受理状态，以及页面确实提供的工单号。不要自行生成工单号，不把“已受理”写成“已恢复”。需要保存记录时使用项目批准的非公开位置，不将邮箱、凭据、验证码或授权链接提交到仓库。执行结束在回复中链接本 skill，并说明实际完成的账号范围。
