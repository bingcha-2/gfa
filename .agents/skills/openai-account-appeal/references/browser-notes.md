# 浏览器操作经验

以下为曾观察到的界面行为，不是稳定接口。页面变化时重新读取页面/无障碍树；不要硬编码元素编号、验证码、邮箱或带令牌 URL。遵守当前浏览器工具允许的操作方式，不用隐藏网络请求或独立浏览器脚本绕过限制。

## 帮助中心

- 支持聊天曾位于 `iframe[name="chatkit"]`；输入框名称可能是“询问支持问题...”或“Ask a support question...”。先确认当前 iframe 和可见输入框。
- 当嵌套 iframe 坐标点击失效时，已定位输入框的填写和 Enter 提交可能有效；确认转接按钮也可在实际支持时使用键盘激活。发送后读取消息，避免重复发送。
- 人工转接曾出现 “Confirm escalation” → “Escalate” → 明确转交支持专员的提示。以最后一步确认判断受理，而不是中间按钮状态。
- 切换账号后确认是目标账号的会话，不向前一个账号工单追加另一账号的问题。

## Mail.com

- 完整邮箱曾因嵌套 mail iframe 出现 “Click target no longer available”。如页面提供官方 “barrier-free inbox” 入口，可改用该入口。
- 如点击入口不跳转，读取实际链接并基于当前 URL 解析后导航；不要构造未观察到的邮箱路径。
- 简版邮箱可从 Inbox 打开最近相关邮件，正文曾位于 `#bodyIFrame`。收件箱显示的账号邮箱及邮件时间用于核验，旧验证码不能用于新登录。

## Outlook

- Outlook 登录入口可能打开新标签页，重新列出标签页并选择实际登录页。
- 验证邮件可能在 Other/其他，而不在 Focused/重点收件箱。
- 可跳过的恢复信息设置不要当作申诉必要步骤；遇到强制验证需要用户完成时停止依赖该验证的操作。
